# 🔐 TOTP 2FA - Реализация на Pure Rust

Полная реализация алгоритма TOTP (Time-based One-Time Password) без использования готовых библиотек для понимания математических принципов.

## 📚 Теоретическая основа

### HOTP - HMAC-based One-Time Password (RFC 4226)

HOTP - это базовый алгоритм для генерации одноразовых паролей на основе счётчика.

**Математическая формула:**
```
HOTP(K, C) = Truncate(HMAC-SHA1(K, C))
```

Где:
- `K` - секретный ключ (shared secret)
- `C` - счётчик (counter), 64-битное число
- `HMAC-SHA1` - хеш-функция с ключом
- `Truncate` - функция "динамического усечения"

### TOTP - Time-based One-Time Password (RFC 6238)

TOTP расширяет HOTP, используя время вместо счётчика.

**Математическая формула:**
```
TOTP = HOTP(K, T)
где T = floor((unix_time - T0) / X)
```

Где:
- `unix_time` - текущее Unix время (секунды с 01.01.1970)
- `T0` - начальное время (обычно 0)
- `X` - временной интервал (обычно 30 секунд)

## 🔬 Пошаговый алгоритм с примером

Разберём генерацию TOTP кода на конкретном примере:

### Исходные данные:
```
Секретный ключ (Base32): JBSWY3DPEHPK3PXP
Секретный ключ (hex):    48656c6c6f21deadbeef
Unix время:              1234567890
Временной шаг:           30 секунд
Количество цифр:         6
```

### Шаг 1: Вычисление счётчика

```
T = floor(unix_time / time_step)
T = floor(1234567890 / 30)
T = 41152263
```

Счётчик в байтах (Big-Endian, 8 байт):
```
0x0000000002744CC7
```

### Шаг 2: Вычисление HMAC-SHA1

```
HMAC-SHA1(Key, Counter) = HMAC-SHA1(
  0x48656c6c6f21deadbeef,
  0x0000000002744CC7
)
```

Результат (20 байт):
```
1f 86 98 69 0e 02 ca 16 61 85 50 ef 7f 19 da 8e 94 5b 55 5a
```

### Шаг 3: Dynamic Truncation (Ключевой момент!)

Это самая интересная часть алгоритма. Она делает HOTP безопасным и компактным.

**3.1. Определение offset:**
```
offset = последний_байт & 0x0F
offset = 0x5a & 0x0F
offset = 10 (0x0A)
```

**3.2. Извлечение 4 байт, начиная с offset:**
```
Байты: [offset..offset+4]
HMAC[10..14] = 50 ef 7f 19

Собираем в 32-битное число (Big-Endian):
binary = 0x50ef7f19
binary = 1357872921 (decimal)
```

**3.3. Обнуление старшего бита (делаем 31-битным):**
```
binary = binary & 0x7FFFFFFF
binary = 0x50ef7f19 & 0x7FFFFFFF
binary = 1357872921 (decimal)
```

### Шаг 4: Получение кода нужной длины

```
code = binary % (10^digits)
code = 1357872921 % 1000000
code = 872921
```

**Финальный TOTP код:** `872921`

## 🎯 Почему Dynamic Truncation?

Dynamic Truncation решает несколько задач:

1. **Переменный offset** - делает невозможным предсказание следующего кода, даже зная предыдущий
2. **Компактность** - из 20 байт HMAC получаем короткий читаемый код
3. **Безопасность** - обнуление старшего бита предотвращает проблемы с signed/unsigned числами

## 🔄 Почему TOTP безопасен?

1. **Односторонняя функция**: Зная HMAC, невозможно восстановить ключ
2. **Привязка ко времени**: Код действителен только 30 секунд
3. **Уникальность**: Каждые 30 секунд генерируется новый счётчик → новый код
4. **Требуется оба фактора**: Знание секретного ключа + текущее время

## 🛠️ Реализация собственного клиента

### Минимальный пример на Rust:

```rust
use hmac::{Hmac, Mac};
use sha1::Sha1;
use std::time::{SystemTime, UNIX_EPOCH};

type HmacSha1 = Hmac<Sha1>;

fn hotp(secret: &[u8], counter: u64) -> u32 {
    let counter_bytes = counter.to_be_bytes();
    
    let mut mac = HmacSha1::new_from_slice(secret).unwrap();
    mac.update(&counter_bytes);
    let hmac_result = mac.finalize().into_bytes();
    
    let offset = (hmac_result[19] & 0x0f) as usize;
    let truncated = u32::from_be_bytes([
        hmac_result[offset],
        hmac_result[offset + 1],
        hmac_result[offset + 2],
        hmac_result[offset + 3],
    ]);
    
    let code = truncated & 0x7fffffff;
    code % 1_000_000
}

fn totp(secret: &[u8]) -> u32 {
    let unix_time = SystemTime::now()
        .duration_since(UNIX_EPOCH)
        .unwrap()
        .as_secs();
    
    let counter = unix_time / 30;
    hotp(secret, counter)
}

fn main() {
    let secret = b"12345678901234567890";
    let code = totp(secret);
    println!("TOTP код: {:06}", code);
}
```

## 🤔 Часто задаваемые вопросы

**Q: Почему используется SHA1, а не SHA256?**  
A: RFC 6238 стандартизировал SHA1 для TOTP. Хотя SHA1 считается устаревшим для других целей, для TOTP он достаточно безопасен, так как атакующему нужно восстановить ключ из HMAC за 30 секунд, что практически невозможно.

**Q: Можно ли использовать другой временной интервал?**  
A: Да, но 30 секунд - стандарт. Google Authenticator по умолчанию использует 30 секунд.

**Q: Что делать если коды не совпадают?**  
A: Проверьте синхронизацию времени. Разница более 1-2 секунд приведёт к несовпадению кодов.

**Q: Можно ли использовать один ключ для нескольких устройств?**  
A: Да, один секретный ключ можно добавить на несколько устройств. Все они будут генерировать одинаковые коды.
